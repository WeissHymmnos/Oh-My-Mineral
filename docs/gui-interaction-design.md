# Mineral GUI 集成式交互设计方案

- 文档状态：集成交互设计草案
- 上游项目：[10knamesmore/Mineral](https://github.com/10knamesmore/Mineral)
- 适用范围：Mineral 桌面 GUI 客户端
- 核心目标：在同一个客户端中集成十套交互方案，允许用户随时切换和组合，同时延续 Mineral 的多源聚合与高效播放体验

## 1. 产品定位

Mineral GUI 是一个统一的多源音乐播放客户端，而不是多个音乐源管理后台或十个彼此独立的播放器界面。

十套交互方案共同运行在同一个应用外壳中，共享搜索、曲库、播放、队列、歌词和 Daemon 状态。用户可以按任务、设备、窗口尺寸和个人习惯切换模式，而不必重新启动应用或放弃当前上下文。

### 1.1 设计目标

1. 让用户以尽量少的步骤完成“查找—播放—继续管理队列”。
2. 在同一个界面中浏览不同音乐源，并构建跨来源播放队列。
3. 同时支持鼠标和键盘，保留 TUI 的高效操作体验。
4. 通过逐字歌词、动态主题色和音频可视化形成沉浸式播放体验。
5. 利用 Client/Daemon 架构，让界面生命周期与播放生命周期相互独立。
6. 对加载、空内容、播放失败、音源未登录和 Daemon 断连提供明确反馈。
7. 将十套方案全部集成为可切换、可组合的交互模式，切换时播放不中断、状态不丢失。
8. 允许用户保存模式、布局、输入偏好和窗口形态，并在下次启动时恢复。

### 1.2 产品边界

GUI 不新增以下产品方向：

- 不推荐算法、排行榜或个性化推荐入口。
- 不提供远端音乐源内容的增加、删除、移动、重命名等管理能力。
- 不把不同音源拆成彼此孤立的应用页面。
- 不把十套方案实现为十份独立的搜索、播放或队列状态。
- 不用鼠标操作替代或削弱完整键盘操作。
- 不让模式切换或关闭 GUI 默认意味着停止后台播放。

收藏、下载、播放队列和本地跨源歌单仅提供上游已经支持的能力。

## 2. 信息架构

GUI 由六个主要区域组成，不同模式可以调整它们的优先级、组合方式和呈现形态：

1. **全局导航**：曲库、歌单、收藏、下载和设置。
2. **搜索**：在线统一搜索与当前列表模糊过滤。
3. **内容浏览**：单曲、艺人、专辑、歌单及其详情。
4. **播放控制**：播放状态、进度、音量、循环模式和上下曲。
5. **播放队列**：当前歌曲、后续歌曲、排序与定位。
6. **正在播放**：封面、歌曲详情、逐字歌词和音频可视化。

音源登录、音源可用状态、下载状态和 Daemon 状态属于全局支撑功能，不应抢占主浏览区域。

### 2.1 统一应用外壳

十套方案共享一个应用外壳，外壳始终负责：

- 全局模式切换入口和当前模式标识。
- 全局搜索、命令面板、通知和设置。
- 当前歌曲、播放进度、队列和歌词状态。
- 音源连接、下载任务和 Daemon 连接状态。
- 键盘焦点、快捷键和模式切换后的上下文恢复。

模式只改变信息的布局和操作方式，不复制底层数据，也不重新创建播放会话。

### 2.2 三层模式模型

为了避免十种方案互相排斥，将其组织为三个可以组合的层次：

1. **工作区模式**：经典三栏、搜索优先、全屏沉浸、队列工作台、封面墙、单栏导航和模块化工作台。
2. **输入模式**：键盘指令中心、鼠标模式、触控与平板模式。输入模式可以叠加在适用的工作区上。
3. **窗口形态**：完整窗口、迷你播放器和系统托盘。进入迷你模式时保留原工作区，返回后恢复。

用户可以从统一的“模式中心”直接选择十套方案中的任意一套，也可以分别调整工作区、输入模式和窗口形态。

## 3. 十套交互方案

## 3.1 方案一：经典三栏桌面播放器

### 布局

- 左栏：音源、歌单、收藏、下载。
- 中栏：专辑或歌单内容、歌曲列表、搜索结果。
- 右栏：正在播放、逐字歌词、音频可视化。
- 底部：封面、进度、播放控制、音量、循环模式和队列入口。

### 核心交互

- 单击选中歌曲，双击播放。
- 右键打开收藏、下载、复制、加入队列等上下文操作。
- 将歌曲拖入队列，或通过拖拽调整队列顺序。
- `/` 过滤当前列表，`Ctrl/Cmd + K` 打开全局搜索。
- 右栏可折叠；窗口缩小时优先收起右栏，再收起左栏。

### 优势与限制

- 优势：符合桌面音乐播放器习惯，功能完整，最适合作为基础界面。
- 限制：形式较常规，需要依靠动画、动态配色、歌词和键盘效率体现 Mineral 特色。

## 3.2 方案二：键盘指令中心

### 布局

默认只显示搜索或内容区与底部播放条。歌词、队列和详情通过浮层展开，减少常驻面板。

### 核心交互

- `Ctrl/Cmd + K` 打开统一命令面板。
- 普通输入用于搜索歌曲，`>` 前缀用于执行应用命令。
- `/` 只过滤当前歌单，支持拼音和模糊匹配。
- `Enter` 播放，`Shift + Enter` 加入队列。
- `Tab` 在搜索结果分类间切换。
- `J/K` 或方向键导航，鼠标作为辅助输入。
- 命令项展示对应快捷键，让用户逐渐掌握操作。

### 优势与限制

- 优势：延续 TUI 用户习惯，检索与播放效率高。
- 限制：存在学习成本，需要清晰的新手提示和可发现的命令入口。

## 3.3 方案三：搜索优先的 Spotlight 模式

### 布局

启动后首先呈现居中的大搜索框。搜索时展开结果区，播放后可收起为紧凑窗口。

### 核心交互

1. 输入关键词，实时展示单曲、艺人、专辑和歌单分组结果。
2. 使用音源标签过滤，默认搜索所有可用来源。
3. 选中结果后显示封面、歌曲信息和详情预览。
4. `Enter` 播放，`Alt + Enter` 加入队列，`Ctrl/Cmd + Enter` 打开详情。
5. 最近搜索与最近播放只用于快速返回，不引入算法推荐。
6. 无结果时分别展示“确实无结果”和“音源不可用或未登录”。

### 优势与限制

- 优势：目标明确的查找—播放路径最短。
- 限制：浏览已有曲库和连续收听专辑的能力较弱。

## 3.4 方案四：全屏沉浸剧场

### 布局

- 动态背景取自当前封面主题色，并随音乐响度轻微变化。
- 大封面和歌曲信息与逐字歌词构成主要画面。
- 底部显示可视化与进度。
- 鼠标静止后隐藏非必要控制，只保留歌词和画面。

### 核心交互

- `Z`、双击封面或全屏按钮进入和退出沉浸模式。
- 点击歌词跳转到对应播放位置。
- `T` 切换原文、翻译和罗马音。
- `V` 切换频谱柱、示波器、瀑布和地形。
- 曲库和队列使用左右抽屉覆盖，不销毁当前播放画面。
- 开启“减少动态效果”后停用响度背景和大幅过渡动画。

### 优势与限制

- 优势：充分发挥 Mineral 的歌词、主题色和可视化能力。
- 限制：不适合频繁检索与整理队列，应作为主界面的一个模式而非唯一界面。

## 3.5 方案五：队列驱动的播放工作台

### 布局

- 左侧：曲库与统一搜索。
- 中间：当前播放队列，突出正在播放与后续歌曲。
- 右侧：当前歌曲详情、歌词和来源信息。

### 核心交互

- 从曲库批量拖入歌曲，构建跨音源队列。
- 拖拽排序，并提供“播放下一首”和“移到队首”等明确操作。
- 队列默认跟随当前歌曲；用户手动浏览后暂停自动跟随。
- 提供“回到正在播放”按钮，对应 TUI 的 `c`。
- 不可用歌曲原位展示失败原因，不阻塞后续队列操作。
- 可从队列创建本地跨源歌单，但不修改远端音乐源内容。

### 优势与限制

- 优势：适合长时间连续收听和频繁安排后续歌曲。
- 限制：队列占用较多空间，简单单曲播放场景下显得较重。

## 3.6 方案六：封面墙浏览模式

### 布局

使用专辑和歌单封面网格代替默认层级列表，顶部提供音源和文字过滤。

### 核心交互

- 首页只展示用户已有专辑、歌单和收藏，不生成推荐内容。
- 悬停封面显示播放、加入队列和详情操作。
- 单击封面在原位置展开歌曲列表，双击播放整个专辑或歌单。
- 右键封面执行收藏、下载或复制操作。
- 支持列表和网格切换，兼顾视觉浏览与高密度操作。
- 大型曲库使用虚拟滚动和按需加载，避免一次渲染全部封面。

### 优势与限制

- 优势：适合按专辑收听，视觉表现力强。
- 限制：单曲检索效率较低，封面加载与大型列表性能要求较高。

## 3.7 方案七：单栏渐进式导航

### 布局

所有内容在同一个主栏中逐级展开：

`音源/歌单 → 歌曲列表 → 歌曲详情`

底部播放条始终固定，队列、歌词和详情共用一个可切换抽屉。

### 核心交互

- 顶部面包屑和返回按钮呈现导航路径。
- 当前列表过滤只影响本页内容。
- 点击歌曲立即播放，更多操作进入上下文面板。
- 同一时间只展开一个辅助抽屉，避免面板争抢空间。
- 小窗口直接沿用该模式，不另外发明一套导航逻辑。

### 优势与限制

- 优势：简单清晰，适合新手和小窗口。
- 限制：无法同时查看曲库、队列和歌词，高阶操作效率较低。

## 3.8 方案八：迷你桌面播放器

### 布局与迷你状态

- 显示封面、曲名、艺人、进度和基础播放控制。
- 悬停展开音量、循环模式与下一首预览。
- 队列以紧凑浮层呈现，支持拖拽排序。
- 点击封面或歌词按钮展开完整主窗口。
- 支持系统托盘和全局快捷键。

### Daemon 交互

- 关闭窗口时提供“仅关闭界面”和“停止播放”两种行为，并允许记住选择。
- 重新打开后恢复当前歌曲、进度、播放状态和队列。
- Daemon 断连时在迷你窗口内直接展示状态和重连入口。

### 优势与限制

- 优势：适合工作时后台听歌，充分发挥 Client/Daemon 架构优势。
- 限制：不能独立承担完整曲库浏览，需要与主界面组合。

## 3.9 方案九：触控与平板模式

### 布局

采用大尺寸歌单和专辑卡片、底部播放条以及可展开的正在播放页面。

### 核心交互

- 底部播放条上滑展开正在播放，下滑收起。
- 歌曲项滑动可加入队列或收藏，同时保留可见按钮，避免操作只能依赖手势。
- 队列通过长按拖拽排序。
- 全屏歌词支持切换歌曲与歌词副轨。
- 搜索页使用大音源筛选标签和内容分类。
- 所有触控操作都有鼠标和键盘对应路径。

### 优势与限制

- 优势：适合平板、触摸屏和客厅设备。
- 限制：信息密度较低，需要单独验证响应式布局与手势状态。

## 3.10 方案十：可组合模块化工作台

### 布局

曲库、搜索、歌曲列表、队列、歌词、详情、可视化、下载状态和 Daemon 状态均为可组合模块。

### 核心交互

- 面板支持折叠、调整宽度和切换位置。
- 提供“浏览”“沉浸”“队列”“简洁”预设，避免首次进入空白工作台。
- 搜索与当前列表过滤保持独立上下文。
- 所有模块共享当前选中歌曲和播放状态，并同步定位。
- 布局只保存在当前 GUI 客户端，不影响 Daemon 或其他客户端。
- 提供“一键恢复默认”，防止布局难以恢复。

### 优势与限制

- 优势：能够覆盖多种高级使用习惯，并容纳其他模式的模块组合。
- 限制：状态同步、响应式布局和测试成本最高，需要统一的模块协议和可靠的布局恢复机制。

## 4. 十套方案的集成与切换设计

十套方案全部属于最终交付范围。它们不是互斥的产品分支，也不是十套独立客户端，而是同一应用外壳下的可切换模式。

| 方案 | 集成层级 | 切换后的主要变化 | 返回时恢复 |
| --- | --- | --- | --- |
| 经典三栏 | 工作区 | 同时展示导航、内容和正在播放 | 面板宽度、选中项、滚动位置 |
| 键盘指令中心 | 输入模式 | 显示命令入口并强化键盘焦点导航 | 命令历史、焦点位置 |
| 搜索优先 | 工作区 | 以全局搜索和结果预览为中心 | 搜索词、筛选条件、结果位置 |
| 全屏沉浸剧场 | 工作区/窗口 | 全屏展示封面、歌词和可视化 | 原工作区、窗口尺寸、浏览位置 |
| 队列驱动工作台 | 工作区 | 将队列移动到其他视图的中心 | 队列滚动位置、跟随设置 |
| 封面墙 | 工作区/内容视图 | 将列表切换为封面网格 | 网格位置、展开项、列表偏好 |
| 单栏渐进导航 | 工作区 | 使用单栏层级导航和共用抽屉 | 导航路径、抽屉状态 |
| 迷你播放器 | 窗口形态 | 收起完整工作区，仅保留播放控制 | 进入前的完整工作区和窗口状态 |
| 触控与平板 | 输入模式 | 增大点击目标并启用手势操作 | 输入偏好、当前工作区 |
| 模块化工作台 | 工作区 | 允许自由组合所有功能模块 | 自定义布局、模块尺寸和位置 |

### 4.1 统一模式中心

应用顶部持续显示“当前模式”按钮。点击后打开模式中心，模式中心必须：

- 列出全部十种方案，而不是只提供几种固定预设。
- 显示每种方案的预览、用途、当前状态和对应快捷键。
- 支持鼠标点击、触控选择、方向键导航和模糊搜索。
- 通过 `Ctrl/Cmd + Shift + M` 打开，也可在命令面板输入 `> 切换模式` 进入。
- 支持“上一模式/下一模式”和“返回上一个模式”，快捷键允许用户重映射。
- 模式切换后显示轻量提示，告知当前模式和返回方式，但不打断播放。

`Z` 仍然是进入和退出沉浸模式的快捷入口；迷你模式、触控模式和其他工作区均可从模式中心直接切换。

### 4.2 切换时的状态保留

所有模式共享以下全局状态，切换时不得重置：

- 当前歌曲、播放/暂停状态、播放进度、音量和循环模式。
- 播放队列、当前队列位置、歌曲来源和下载状态。
- 在线搜索词、音源筛选、搜索结果和当前列表过滤词。
- 当前选中歌曲、歌词副轨、可视化样式和通知。
- Daemon 连接以及正在执行的后台任务。

每种模式另外保存自己的视图状态，包括滚动位置、展开项、面板尺寸、焦点位置和导航栈。切回该模式时恢复，而不是回到默认首页。

### 4.3 模式组合规则

- **键盘指令中心**可叠加到所有工作区；在迷你模式中调用命令面板时，以浮层显示，不强制展开完整窗口。
- **触控与平板模式**可叠加到经典三栏、搜索、队列、封面墙、单栏、沉浸和模块化工作区。
- **迷你播放器**是窗口形态。进入前记录原工作区，退出后完整恢复，不将原工作区改成默认三栏。
- **沉浸模式**覆盖当前工作区但不销毁它；退出后回到进入前的工作区和焦点。
- **封面墙**既可作为独立工作区，也可作为经典三栏、单栏和模块化工作区中的内容视图。
- **模块化工作台**可以容纳其他模式的模块和布局预设，但不能创建第二份播放或队列状态。
- 用户可以将常用组合保存为自定义模式，例如“封面墙 + 键盘输入”“队列工作台 + 触控输入”。

### 4.4 自动切换与手动选择

- 窗口变窄时可以建议或自动切换为单栏模式，检测到触摸设备时可以建议触控模式。
- 自动切换必须由用户设置控制；用户手动选定模式后，不得仅因一次窗口缩放就永久覆盖其偏好。
- 自动布局变化与显式模式切换使用同一套状态保存机制。
- 用户可以锁定当前工作区和输入模式，也可以恢复“跟随窗口与设备”的自动行为。

### 4.5 偏好保存与恢复

- 保存当前工作区、输入模式、窗口形态和各模式视图状态。
- 自定义模块布局和组合模式只保存在当前 GUI 客户端，不写入 Daemon。
- 下次启动默认恢复上次模式；若窗口或设备不再适用，则提供可撤销的适配切换。
- 提供“恢复默认模式”和“重置全部布局”，两者都不得影响播放队列和远端音乐源内容。

## 5. 统一主界面的核心流程

### 5.1 查找并播放

1. 用户通过全局搜索或左侧歌单进入内容列表。
2. 搜索结果默认跨音源聚合，并显示单曲、艺人、专辑和歌单分类。
3. 用户可以使用音源标签缩小范围。
4. 双击歌曲或按 `Enter` 播放，播放条与正在播放区域同步更新。
5. 加载期间保留界面响应，并显示当前歌曲的加载状态。
6. 播放失败时展示可理解的错误原因和重试入口，不静默跳到无关页面。

### 5.2 管理播放队列

1. 通过底部队列按钮或 `Tab` 打开队列。
2. 当前歌曲固定在视觉焦点附近，用户可关闭自动跟随。
3. 支持拖拽、键盘移动和右键菜单三种排序方式。
4. 加入队列后不自动打断当前播放。
5. 队列操作只在本地播放上下文中生效，不修改远端歌单。

### 5.3 查看歌词并进入沉浸模式

1. 在右侧正在播放区域查看歌词和歌曲详情。
2. 使用 `T` 切换歌词副轨。
3. 使用 `Z` 展开全屏沉浸模式。
4. 退出后恢复此前窗口尺寸、浏览位置和滚动位置。

### 5.4 关闭界面但继续播放

1. 如果 Daemon 正在运行，关闭 GUI 不应隐式终止播放。
2. 关闭行为遵循用户设置；需要询问时提供“仅关闭界面”和“停止播放”。
3. 下次启动后从 Daemon 恢复状态，而不是创建一份独立播放状态。
4. Daemon 不可用时明确区分“播放已停止”和“界面暂时无法获取状态”。

### 5.5 切换交互模式

1. 用户点击顶部当前模式按钮，或按 `Ctrl/Cmd + Shift + M` 打开模式中心。
2. 模式中心展示全部十种方案，用户可以直接选择，也可以搜索“歌词”“队列”“迷你”等关键词。
3. 切换期间保持音频播放和后台任务运行，不清空搜索、不重建队列。
4. 新模式接管同一组全局状态，并恢复该模式上次保存的视图状态。
5. 用户选择“返回上一个模式”后，恢复之前的模式组合、焦点、滚动位置和窗口形态。
6. 用户可以将当前工作区、输入模式和窗口形态保存为新的组合模式。

## 6. 通用交互规范

### 6.1 默认操作映射

| 操作 | 鼠标/触控 | 键盘 |
| --- | --- | --- |
| 播放或暂停 | 点击播放按钮 | `Space` |
| 播放选中歌曲 | 双击歌曲 | `Enter` |
| 加入队列 | 右键菜单或拖入队列 | `Shift + Enter` |
| 下一首或上一首 | 点击对应按钮 | `N` / `P` |
| 当前列表过滤 | 点击列表搜索框 | `/` |
| 全局搜索或命令 | 点击顶部搜索框 | `Ctrl/Cmd + K` |
| 打开模式中心 | 点击顶部当前模式 | `Ctrl/Cmd + Shift + M` |
| 返回上一个模式 | 在模式中心选择返回 | 可配置的“返回上一模式”快捷键 |
| 打开或关闭队列 | 点击队列按钮 | `Tab` |
| 切换歌词副轨 | 点击歌词副轨标签 | `T` |
| 进入或退出沉浸模式 | 点击沉浸按钮 | `Z` |
| 返回 | 点击返回按钮 | `Esc` / `Backspace` |
| 调整队列顺序 | 拖拽或长按拖拽 | `Ctrl + J/K` |
| 回到正在播放 | 点击定位按钮 | `C` |
| 查看快捷键 | 点击帮助按钮 | `?` |

快捷键最终应与上游配置能力对齐；文本输入框获得焦点时，字母快捷键不得劫持输入。模式切换快捷键在普通窗口、沉浸模式和迷你窗口中均应可用。

### 6.2 搜索规范

- 在线搜索与当前列表过滤必须采用不同视觉上下文，避免用户混淆。
- 搜索结果显示来源标识，但默认不按来源拆成多个页面。
- 搜索期间保留上一次有效结果，并明确显示正在更新，避免列表闪烁。
- 无结果、网络错误、音源未登录和部分音源失败必须呈现不同状态。
- 清空搜索后恢复之前的浏览位置和滚动位置。
- 从搜索优先模式切换到其他模式时保留同一搜索词、筛选条件和结果；返回搜索优先模式时恢复结果滚动位置。

### 6.3 歌曲与队列规范

- 单击选中，双击播放，避免单击列表项就意外打断音乐。
- 当前播放歌曲在列表和队列中均有一致标识。
- 同一首歌在不同来源出现时保留来源信息，不静默合并或替换。
- 歌曲不可用后保留用户上下文，并提供重试或移除出本地队列的操作。
- 批量操作必须显示作用对象数量，避免误操作整个队列。
- 所有工作区和自定义模块只能操作同一个播放队列，模式切换不得复制、清空或重新排序队列。

### 6.4 歌词与可视化规范

- 歌词滚动可被用户手动打断；停止操作一段时间后恢复自动跟随。
- 提供“回到当前歌词”入口。
- 歌词翻译、罗马音和可视化样式在切歌和模式切换后保留用户选择。
- 动态主题色不能降低文字对比度。
- 可视化不能阻塞搜索、滚动、拖拽、模式切换和播放控制。
- 从沉浸模式返回后，原工作区的歌词位置和浏览上下文保持不变。

### 6.5 反馈与通知

- 普通成功操作使用轻量反馈，错误提供原因和下一步动作。
- 多个通知按时间堆叠，可逐条关闭，不遮挡主要播放控制和模式切换入口。
- 长任务显示进度，并允许界面继续执行其他操作和切换模式。
- 不用单一颜色表达错误、来源或播放状态，同时提供文字或图标。
- 模式切换提示不打断输入，也不覆盖错误、登录和 Daemon 断连等重要反馈。

### 6.6 模式切换规范

- 所有模式使用相同的歌曲操作语义、搜索数据和播放状态。
- 切换动画只改变视觉布局，不延迟实际播放控制和模式中心打开。
- 模式中心关闭后，将焦点交还给触发控件或新工作区中的逻辑位置。
- 当前模式不可用时说明原因，并保留用户原模式，不得静默切换到无关界面。
- 切换失败不能影响 Daemon、音频播放和已保存的布局配置。

## 7. 响应式行为与模式适配

### 宽窗口

默认可显示经典三栏，也可以保持用户选择的搜索优先、队列工作台、封面墙或模块化布局，不强制回到三栏。

### 中等窗口

优先收起右侧正在播放区域，将歌词与详情放入抽屉；左导航可缩为图标。其他工作区按照各自规则折叠，而不是一律替换为三栏。

### 窄窗口

在自动适配开启时切换为方案七的单栏渐进导航，队列、歌词和详情共用抽屉。用户手动锁定模式时，只压缩当前布局并提示单栏模式可选。

### 迷你窗口

进入方案八后只保留当前歌曲、进度、播放控制、队列和模式中心入口。退出迷你窗口时恢复进入前的完整工作区，而非使用固定默认布局。

### 触摸设备

在自动适配开启时建议启用触控输入模式，保留当前工作区。用户可以在任意工作区中手动开启或关闭触控输入，不必进入独立应用。

所有自动和手动布局切换都必须保留当前搜索词、选中项、滚动位置、队列位置和播放状态，并允许用户撤销最近一次自动切换。

## 8. 集成版本交付范围

### 8.1 统一基础能力

- 统一应用外壳、全局状态模型和模式中心。
- 音源状态与用户已有曲库、歌单浏览。
- 跨音源在线搜索和当前列表模糊过滤。
- 播放、暂停、上下曲、进度、音量和循环模式。
- 统一播放队列、排序和定位当前歌曲。
- 当前歌曲详情、逐字歌词和歌词副轨切换。
- 收藏、下载等上游已支持的歌曲操作。
- 音频可视化、封面主题色和减少动态效果。
- Daemon 连接状态、断连反馈及关闭 GUI 后继续播放。
- 鼠标、键盘和触控主流程，以及完整的加载、错误与空状态。
- 模式与布局偏好保存、恢复、撤销自动切换和重置能力。

### 8.2 十种可切换方案

最终集成版本必须全部提供：

1. 经典三栏桌面播放器。
2. 可叠加到各工作区的键盘指令中心。
3. 搜索优先的 Spotlight 工作区。
4. 可进入和退出的全屏沉浸剧场。
5. 队列驱动的播放工作台。
6. 可独立使用也可嵌入其他工作区的封面墙。
7. 可手动选择也可自动适配的单栏渐进导航。
8. 能恢复原工作区的迷你桌面播放器。
9. 可叠加到各工作区的触控与平板输入模式。
10. 能容纳功能模块、保存自定义布局的模块化工作台。

阶段划分只代表实施顺序，不代表将其中任何方案排除在最终集成版本之外。

### 8.3 推荐实施顺序

1. **统一状态与外壳**：先实现共享播放、搜索、队列、导航和模式状态，再实现经典三栏与单栏布局，验证无状态切换。
2. **任务工作区**：接入搜索优先、键盘指令中心、队列工作台和封面墙，验证搜索与队列在各模式间同步。
3. **窗口与输入形态**：接入沉浸剧场、迷你播放器和触控模式，验证窗口恢复与输入模式叠加。
4. **模块化与组合模式**：接入模块容器、自定义布局、组合模式和持久化，完成十种模式的统一切换与回归验证。

### 8.4 不进入路线图的方向

- 算法推荐和排行榜。
- 远端音乐源内容管理。
- 与查找—播放主链路无关的社交功能。
- 为不同模式分别维护独立播放核心或独立 Daemon。

## 9. 可用性与无障碍要求

- 所有核心功能和全部模式切换均可通过键盘完成，焦点位置清晰可见。
- 模式中心提供文字名称和用途说明，不只使用图标或预览颜色。
- 图标按钮具有文字提示，来源和状态不只依赖颜色。
- 正文、歌词和播放控制在动态背景下保持足够对比度。
- 支持减少动态效果，关闭非必要动画后不影响功能和模式切换。
- 动画期间不丢失输入，不阻塞播放、导航和模式中心。
- 大列表采用虚拟化，滚动和搜索不能因封面加载明显卡顿。
- 触控模式提供足够大的点击目标，所有手势都有可见按钮和键盘替代路径。
- 自动模式切换必须有提示并可撤销，避免用户突然失去当前操作上下文。

## 10. 集成版本验收标准

1. 模式中心列出全部十种方案，用户能通过鼠标、触控和键盘打开并切换。
2. 在十种方案之间连续切换时，应用不重启，音频不中断，当前歌曲、进度和队列始终一致。
3. 在线搜索词、列表过滤词、筛选条件、选中歌曲、歌词副轨和可视化样式在切换后不丢失。
4. 每种模式再次进入时恢复自己的滚动位置、展开项、面板尺寸、焦点和导航路径。
5. 经典三栏、搜索优先、队列工作台、封面墙、单栏导航和模块化工作台均可作为工作区直接选择。
6. 键盘指令中心可在所有工作区中调用，不会创建另一份搜索或播放状态。
7. 进入和退出沉浸模式后，恢复进入前的工作区、窗口尺寸和浏览位置。
8. 进入和退出迷你播放器后，恢复进入前的模式组合；迷你状态下仍可进行播放控制和队列操作。
9. 触控模式可以叠加到各工作区，且手势操作都有可见控件和键盘替代路径。
10. 封面墙可以独立使用，也能在支持的内容区域中切换为列表，切换前后选中项和位置一致。
11. 队列工作台与其他模式操作同一队列，拖拽、触控和键盘排序结果实时同步。
12. 模块化工作台可以保存、恢复和重置布局，各模块共享同一选中歌曲和播放状态。
13. 用户能保存“工作区 + 输入模式 + 窗口形态”的组合，并在重启应用后恢复。
14. 自动响应式切换可关闭、可锁定、可撤销；手动模式偏好不会被一次窗口缩放永久覆盖。
15. 音源未登录、部分搜索失败、歌曲不可用和 Daemon 断连在所有模式中均有一致且可操作的反馈。
16. 关闭 GUI 后播放行为符合设置，重新打开后能恢复 Daemon 状态及上次模式组合。
17. 模式切换或布局加载失败时，播放和队列不受影响，并保留可用的返回路径。
18. 界面不出现推荐、排行榜或远端音乐源内容管理入口。
